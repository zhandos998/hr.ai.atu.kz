# Исправления по проверке проекта

Дата: 15 октября 2026 года. Работа выполнена локально, сервер не изменялся.

## Безопасность

- Чтение заявки требует авторизации и проверки доступа через ApplicationPolicy.
- Документы кандидатов и кадровых процессов хранятся на закрытом диске documents.
- Для документов кандидатов выдаются подписанные ссылки со сроком 15 минут; после истечения нужно обновить карточку. Кадровые файлы доступны только через авторизованный API с проверкой финансовых прав.
- Старые публичные пути заблокированы в nginx и Apache. Команда documents:privatize переносит существующие файлы с проверкой SHA-256, сохраняя пути в БД. Повторный запуск допустим.
- Загрузка проверяет содержимое и разрешённые расширения до записи пакета файлов. Ответы файлов имеют контролируемый Content-Type, nosniff, private/no-store и CSP sandbox.
- Содержание, документы и комиссия кадровой заявки блокируются после первого решения. Изменения и голосование сериализуются блокировкой строки БД.
- UserSeeder и KshitCommissionSeeder сохраняют пароли и роли существующих пользователей.
- SQL-дампы, SQLite и служебные копии исключены из Docker context.
- Добавлены ограничения попыток входа и запросов писем. При смене пароля отзываются остальные токены, при сбросе пароля и смене email отзываются старые токены. Отменяются устаревшие запросы смены email.
- Публичные вакансии не возвращают контакты комиссии. Вложенный вход от имени пользователя запрещён.

## Рабочие Процессы

- Комплаенс ППС позволяет сохранить данные и установить решение clear/flagged.
- Миграция академической структуры сохраняет административное подразделение под кафедрой через departments.academic_unit_id. Исправлен порядок удаления внешнего ключа при откате конкурсов.
- При изменении типа вакансии с существующими заявками возвращается ошибка валидации.
- Администратор не может попасть в состав кадрового согласования, где ему недоступно голосование.
- Загрузка резюме требует своей заявки и корректного этапа; повторная загрузка заменяет резюме этой заявки.
- Сохранение отдельного этапа и удаление документов не стирают несохранённый текст и выбранные файлы других секций.
- Просмотр кадрового PDF не запускает дополнительное скачивание.
- Фильтры и пагинация списка сохраняются в URL и при возврате из карточки.
- Рабочий раздел доступен на мобильном экране. Переведены формы, действия, статусы и сообщения интерфейса на казахский через общий словарь; пользовательские данные не переводятся.

## Производительность И Проверки

- На импортированной SQLite-копии: 25 заявок — 10 SQL-запросов и 66 248 байт вместо 677 запросов и примерно 495 КБ. На 100 заявок также 10 запросов, 263 250 байт. Это локальный замер, не нагрузочный тест сервера.
- Полная SQLite-проверка: 96 тестов, 579 проверок.
- Выборка проверок безопасности, рабочих процессов, сидеров и пагинации повторена на отдельной MySQL-базе: 24 теста, 97 проверок.
- Свежий исходный серверный дамп восстановлен в отдельную локальную MySQL-базу. Миграции, откат пяти новых миграций и повторный запуск прошли без потери 464 пользователей и 424 заявок. Должностей с отсутствующими подразделениями нет.
- Production-сборка React прошла. Браузером проверены вход RU/KK, возврат на страницу списка, сохранность черновика и файлов, комплаенс ППС, мобильная навигация и профиль KK, просмотр кадрового PDF. Ошибок JavaScript и ответов 5xx в этих сценариях нет.
- Уязвимые PHP-зависимости обновлены совместимыми версиями в пределах Laravel 12. composer audit и npm audit --omit=dev не нашли известных уязвимостей на момент проверки.
- Синтаксис backup-database.sh и docker compose config проверен. Скрипт использует --no-tablespaces, проверяет gzip и окончание дампа перед публикацией и ротацией.

## Обновление Сервера

Порядок команд находится в [SERVER_COMMANDS.txt](../SERVER_COMMANDS.txt), раздел 2.
Нужны резервные копии БД и storage, пересборка образов, migrate --force и documents:privatize.
Не запускать migrate:fresh и db:seed для этого обновления. Не удалять Docker volumes.
Откат на старый образ без согласованного восстановления storage невозможен: старый код ищет документы в public.

## Ограничения

- Docker daemon локально не запущен: новая сборка контейнеров и запуск полного Docker-окружения не проверены.
- SMTP, OpenAI и КМК требуют отдельной проверки с рабочими настройками. Реальная доставка писем не подтверждена.
- Серверные вложения вместе с дампом БД не скачивались; проверка всех существующих файлов требует серверной копии storage.
- Нагрузочные и конкурентные испытания не выполнялись. Четырёхзначные пароли остаются слабой политикой, несмотря на ограничение попыток входа.
- Архитектурное разбиение крупных контроллеров на сервисы и API Resources остаётся отдельной задачей; произвольного переписывания проекта в этом исправлении нет.
